# MailMind 需求分析

> 版本 v1.0 ｜ 日期 2026-10-28 ｜ 对应系统版本 0.1.0

## 1. 背景与问题

企业/个人的收件箱同时承担三类互相干扰的工作：

| 问题 | 现状 | 后果 |
|---|---|---|
| 垃圾邮件与钓鱼 | 靠服务商默认规则，误杀与漏杀并存 | 漏杀浪费时间，误杀丢客户 |
| 人工分类 | 客服/财务/销售靠肉眼归档 | 响应慢，漏跟进 |
| 重复问题回复 | 同一批 FAQ 每天手打 | 人力浪费，回复口径不一致 |

MailMind 要解决的是"**从邮件进来到回复出去**"这条链路的自动化，并且把风险最高的"发出去"这一步
置于可控的审核之下。

## 2. 产品目标

1. **垃圾邮件不漏、更不误杀**：优先保证不误杀重要邮件，其次才是召回。
2. **分类可直接驱动动作**：类别决定"自动回复 / 归档 / 转人工"。
3. **自动回复有依据**：只回答知识库里有的内容，不确定就不回答。
4. **可解释、可追溯**：每条判定都能回答"为什么"，每个自动动作都有审计。
5. **可离线运行、可测试**：不依赖外部模型服务也能完整跑通，便于交付与验收。

## 3. 成功指标（验收口径）

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 垃圾邮件召回 | ≥ 0.70（小样本基线，生产目标 0.98） | 独立标注集，见 `tests/test_quality.py` |
| 误杀率（FP） | ≤ 0.25（基线），生产目标 ≤ 0.1% | 同上，误杀回归集 |
| 分类 macro-F1 | ≥ 0.85（生产目标） | 标注集 + 混淆矩阵 |
| 草稿可用率 | ≥ 60% 可直接发送 | 审核队列统计（发送/修改/拒绝） |
| 首次响应时间 | 自动回复 ≤ 30s；人工 ≤ 4h | 邮件时间戳 |
| 自动回复事故 | 0（敏感信息/乱承诺/回环） | 审计 + 抽检 |
| 同步幂等 | 重复投递 0 重复入库 | `(account_id, message_id)` 唯一约束 |

## 4. 干系人

| 角色 | 关注点 | 主要操作 |
|---|---|---|
| 客服/运营 | 回复快、别回错 | 审核队列、AI 起草、隔离区放行 |
| 财务/销售 | 重要邮件别被拦 | 白名单、规则 |
| 系统管理员 | 稳定、安全、可追溯 | 账号/凭据、规则、重训、审计、指标 |
| IT/安全 | 凭据安全、合规 | 密钥管理、HTTPS、数据保留 |
| 外部客户 | 及时、准确的回复 | 无感知（只收到邮件） |
| 模型服务（LLM） | — | 起草与低置信度兜底 |

## 5. 典型业务场景

**S1 客户咨询退货**
邮件到达 → 判为 `ham` → 分类 `consult` → 通过回复闸门 → 检索到"退换货政策" → 起草 → 护栏通过 →
进入审核队列 → 客服改一句话 → 发送。全过程 < 5 分钟。

**S2 营销/钓鱼邮件**
中奖话术 + IP 直连链接 + 认证失败 → score ≥ 0.95 → 进隔离区；用户可在隔离区一键放行并加白。

**S3 财务对账单**
分类 `billing`（不在自动回复白名单）→ 只归档、不回复、不打扰。

**S4 群发通知/自动回复**
带 `List-Id` 或 `Auto-Submitted` → 回复闸门直接拦截，避免机器人互回。

**S5 误杀投诉**
客户邮件被拦 → 客服在隔离区放行 → 系统自动把该域加入白名单 → 反馈进入训练集 → 下次重训生效。

## 7. 非功能需求

| 维度 | 要求 | 实现说明 |
|---|---|---|
| 吞吐 | 单实例 ≥ 50 封/秒解析入库 | 同步逐封处理，可水平扩展 worker |
| 时延 | 到达→判定 ≤ 5s；自动回复 ≤ 30s | 规则+NB 毫秒级；LLM 仅模糊区/低置信度 |
| 可用性 | 单组件故障不阻断收信 | LLM 失败降级模板；Redis 不可用降级内存 |
| 安全 | 凭据加密、接口鉴权、审计 | Fernet + `X-API-Key` + 审计表 |
| 隐私 | 送 LLM 前 PII 打码；可删除 | `mask_pii`、软删除 |
| 可维护 | 阈值配置化、模型可替换 | `Settings` + `Embedder`/`LLMGateway` 协议 |
| 可测试 | 全离线、确定性 | 292→325 个测试，不依赖外网/邮箱 |
| 可移植 | SQLite 开发、PG 生产；本地/S3 存储 | 同一套 ORM + Alembic |

## 8. 约束与假设

- 每个账号只同步一个文件夹（默认 INBOX）；多文件夹需多账号。
- Gmail/Graph 使用 access token（短期），过期需通过 `PATCH /accounts/{id}` 回写。
- 自动回复默认 `review` 模式；`auto` 模式仍需通过全部闸门。
- 单租户单组织；多租户需要额外加 `tenant_id` 与行级过滤。
- 不做 MTA：不在 SMTP 会话阶段拒收，只做入库后的判定与隔离。

## 9. 范围外（本期不做）

移动端 App、日历集成、工单系统对接、多语言界面、模型在线学习（只有批量重训）、
邮件全文搜索引擎（当前用 SQL + 内存检索）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 误杀重要邮件 | 业务事故 | 三档动作 + 白名单 + 误杀回归集 |
| 自动回复乱承诺 | 法律/商务 | 引用强制、敏感词转人工、默认审核 |
| 机器人互回 | 邮件风暴 | RFC 3834 全检 + 冷却 + 线程深度 |
| 自身回复进垃圾箱 | 送达失败 | 要求 SPF/DKIM/DMARC + 统一出口 |
| 模型漂移 | 效果下降 | 反馈重训 + 指标监控 + 规则快速通道 |
| 凭据泄漏 | 安全事件 | 加密存储、密钥不轮换则不解、HTTPS |

## 11. 验收标准（DoD）

1. 325 个自动化测试全部通过（`make test`），核心链路有集成测试；
2. 演示数据可一键生成，管理台 9 个页面可用；
3. 垃圾过滤在独立样本上召回 ≥ 0.7、误杀 ≤ 0.25，且无正常邮件被隔离；
4. 自动回复：无引用/空回复/PII 泄露一律拒绝，敏感承诺与提示注入转人工；
5. 审计可追溯每一次自动发送、放行与规则变更；
6. 文档齐备：README、quickstart、exp.md、本目录需求与图示。
