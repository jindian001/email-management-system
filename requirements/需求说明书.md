# MailMind 需求说明书

> 版本 v1.0 ｜ 日期 2026-10-28 ｜ 对应系统 0.1.0 ｜ 需求来源：[需求分析.md](需求分析.md)

## 1. 系统边界与上下文

```
        ┌──────────────┐        IMAP / Gmail API / Graph        ┌──────────────┐
        │  外部邮箱服务  │ ◄───────────────────────────────────► │              │
        └──────────────┘                                       │              │
        ┌──────────────┐            SMTP / Gmail API            │   MailMind   │
        │  收件人邮箱    │ ◄───────────────────────────────────► │              │
        └──────────────┘                                       │              │
        ┌──────────────┐         OpenAI 兼容 /chat/completions  │              │
        │  LLM 服务     │ ◄───────────────────────────────────► │              │
        └──────────────┘                                       └──────┬───────┘
                                                                     │ HTTPS
                                                              ┌──────▼───────┐
                                                              │ 管理台/脚本   │
                                                              └──────────────┘
```

**系统内**：接入、解析、判定、分类、回复编排、知识库、审计、管理台、任务调度。
**系统外**：邮件传输（MTA）、模型训练数据标注平台、企业 IM/工单系统。

## 2. 角色与权限

| 角色 | 认证方式 | 可做 | 不可做 |
|---|---|---|---|
| 运营/客服 | `X-API-Key` + 管理台 | 看邮件、审核/改稿、放行隔离、查审计 | 改规则、删账号 |
| 管理员 | `X-API-Key` | 全部接口：账号、规则、知识库、重训、删除 | — |
| 定时任务/系统 | 内部调用 | 同步、处理、重训 | — |
| 匿名 | 无 | 仅 `/health`、`/ui/**`、`/docs` | 一切业务接口 |

> 当前为单个共享 key，没有细粒度 RBAC；上表是"应当具备"的权限设计，落地为共享 key + 操作审计。

### UC-01 接入邮箱账号

- **触发**：管理员在「账号」页提交或调用 `POST /api/v1/accounts`。
- **前置**：已获得邮箱的 IMAP/SMTP 地址与**应用专用密码**（或 Gmail/Graph 的 token）。
- **主流程**：校验邮箱格式 → 加密 `secret`（Fernet）→ 落库 `accounts`（provider、config、secret_enc）→ 返回账号。
- **异常**：邮箱重复 → 409；格式非法 → 422；加密失败 → 500。
- **后置**：账号可用于同步。
- **验收**：`GET /accounts` 能看到账号，`secret_enc` 非明文。

### UC-02 增量同步邮件

- **触发**：`POST /accounts/{id}/sync`、CLI `mailmind sync`、或定时任务。
- **前置**：账号存在且 `status=active`。
- **主流程**：
  1. 连接器按游标拉取（IMAP 用 `last_uid`/`uid_validity`，Gmail 用 `historyId`，Graph 用时间戳）；
  2. 逐封 `ingest_raw`：大小校验 → 解析 → 按 `Message-ID` 去重 → 原始 EML 写对象存储 → 建 `mails` 行 → 附件元数据；
  3. 对每封调用处理链（判定 + 分类 + 可能的回复编排）；
  4. 更新账号游标与 `last_synced_at`，提交事务。
- **异常**：UIDVALIDITY 变化 → 全量重扫；单封解析失败 → 记录 error 并继续；连接失败 → 返回 400/500，游标不前进。
- **后置**：新邮件进入 `classified` / `quarantined` 等状态。
- **验收**：重复同步不产生重复数据；`fetched/ingested/duplicates/failed` 统计正确。

### UC-03 过滤垃圾邮件

- **触发**：每封新邮件的处理链。
- **主流程**：白名单 → 强规则（黑名单/认证失败/发件人信誉/主题正则）→ 朴素贝叶斯 + 启发式取最大 →
  模糊区（0.20–0.80）调 LLM 复核并按 0.5/0.5 融合 → 按阈值给出 `pass` / `tag` / `quarantine`。
- **后置**：`mail_verdicts` 写入分数、动作、原因、模型版本。
- **验收**：三档动作符合阈值；每条判定有 `spam_reasons`；误杀率满足验收口径。

### UC-04 自动分类

- **触发**：判定结果为非垃圾（或 tag）之后。
- **主流程**：类别规则 → 朴素贝叶斯（置信度 ≥ 0.60）→ 低置信度走 LLM few-shot。
- **异常**：垃圾邮件直接记 `spam`，不进入业务分类。
- **后置**：`category`、`category_scores`、`category_reason` 落库。
- **验收**：类别 ∈ 配置集合；类别与自动回复白名单一致（有守护测试）。

### UC-05 生成回复草稿

- **触发**：回复闸门放行后自动执行，或人工点「AI 起草」。
- **主流程**：拼查询（主题+正文）→ 混合检索 top-20 → 重排 top-5 → 过滤低分 → LLM/模板生成结构化草稿
  （intent/subject/body/confidence/citations）→ 护栏 → 计算置信度 → 状态：`send` / `pending_review` / `rejected`。
- **异常**：无检索结果 → 无引用 → 护栏拒绝；LLM 失败 → 降级模板。
- **后置**：`reply_drafts` 落库（含 model、citations、risk_flags）。
- **验收**：草稿必须带有效引用；无依据时不会产生可发送草稿。

### UC-06 审核并发送回复

- **触发**：客服在审核队列点「通过并发送」，或 `POST /replies/{id}/approve`、`POST /mails/{id}/reply/send`。
- **主流程**：允许改正文（记录 `edited_diff`）→ 组装 MIME（`In-Reply-To`、`References`、`Auto-Submitted`）→
  按账号选择 SMTP/Gmail 发送 → 成功则草稿 `sent`、邮件 `replied`、占冷却、写审计。
- **异常**：发送失败 → 草稿 `failed`，不占冷却，可重试；草稿已被发送 → 拒绝重复发送。
- **验收**：收件人收到的回复归属原会话；失败可见且可重试。

### UC-07 处置隔离区邮件

- **主流程**：列表 → 放行（自动写 allowlist，状态改 `classified`、判定改 `ham`）或删除（软删除 `deleted`）。
- **后置**：审计记录动作。
- **验收**：放行后该发件域不再被拦；删除后不出现在隔离区。

### UC-08 维护规则

- **主流程**：`POST/PATCH/DELETE /rules`，支持 allowlist/blocklist/keyword/header/auth/sender_reputation/category/subject_regex。
- **约束**：改动**立即生效**（每次处理都从库加载规则集）。
- **验收**：新增黑名单后下一封即可命中；可用 `/rules/test` 试算。

### UC-09 维护知识库

- **主流程**：`POST /kb/documents`（按空行切片，存向量）→ `GET /kb/search` 验证召回 → 删除。
- **验收**：检索能命中刚导入的内容；切片数量合理。

### UC-10 反馈与重训

- **主流程**：用户/审核员提交反馈（spam/category/reply_quality，用户权重 ×3）→ `POST /admin/retrain` 或 `mailmind train` →
  重建模型 → 运行时热替换。
- **验收**：反馈出现在列表；重训后模型版本更新；类别新增时旧模型自动判 stale 并重训。

### UC-11 查看审计与指标

- **主流程**：`GET /audit`（按动作前缀过滤）、`GET /metrics/overview`。
- **验收**：自动发送/放行/规则变更/凭据更新均有记录，带 `trace_id`。

### UC-12 更新账号凭据

- **场景**：Gmail/Graph token 过期、邮箱改密码、临时暂停。
- **主流程**：`PATCH /accounts/{id}` 更新 `secret` / `config` / `status`，新 `secret` 用当前密钥重新加密，写审计。
- **验收**：更新后同步可用；旧凭据不再生效；不需要删除账号。

## 4. 接口需求（摘要）

| 分组 | 端点 | 说明 |
|---|---|---|
| 系统 | `GET /api/v1/health` | 公开；含 `auth` 状态 |
| 账号 | `POST/GET/PATCH/DELETE /accounts`、`/accounts/{id}` | 含凭据更新、暂停 |
| 同步 | `POST /accounts/{id}/sync` | 增量；`limit` 控制单批 |
| 投递 | `POST /accounts/{id}/ingest` | 直接投一封原始邮件（联调/回放） |
| 邮件 | `GET /mails`、`/mails/{id}`、`/raw`、`/thread` | 支持 `q/status/category/cursor` |
| 反馈 | `POST /mails/{id}/feedback` | spam/category/reply_quality |
| 隔离 | `GET /quarantine`、`POST /{id}/release`、`/{id}/delete` | 放行可加白 |
| 回复 | `GET /replies`、`POST /{id}/approve`、`/{id}/reject`、`POST /mails/{id}/reply/send` | 审核闭环 |
| 规则 | `GET/POST/PATCH/DELETE /rules`、`POST /rules/test` | 试算不落库 |
| 知识库 | `GET/POST/DELETE /kb/documents`、`GET /kb/search` | 切片+检索 |
| 运维 | `GET /audit`、`GET /feedback`、`POST /admin/retrain` | 审计/反馈/重训 |

通用约定：统一 `X-API-Key` 鉴权；错误返回 `{"detail": "..."}`；分页用 `cursor`；写操作幂等（Message-ID / 草稿状态机）。

## 5. 数据需求

| 表 | 关键字段 | 保留策略 |
|---|---|---|
| `accounts` | email、provider、config、secret_enc、last_uid、uid_validity | 长期 |
| `mails` | message_id、thread_id、from/to、subject、text_body、headers、raw_object_key、status | 可配置（默认 2 年） |
| `attachments` | filename、content_type、sha256、object_key、is_risky | 随邮件 |
| `mail_verdicts` | spam_score/label/action/reasons、category/scores/reason、model_versions | 随邮件 |
| `reply_drafts` | intent、body、citations、confidence、status、reviewer、edited_diff | 长期（审计） |
| `rules` | kind、payload、action、priority、enabled | 版本留痕 |
| `kb_documents` | title、content、embedding、source | 长期 |
| `feedback` | task、label、weight、source | 长期（训练数据） |
| `audit_logs` | actor、action、target、detail、trace_id | ≥ 1 年 |

- 原始 EML：对象存储，按 `sha256` 内容寻址，可用于重放；
- 凭据：仅存密文（Fernet），解密需要 `MAILMIND_SECRET_KEY`；
- 敏感字段（手机号/证件/银行卡）在送 LLM 前打码。

## 6. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | `spam_score ≥ 0.95` → 隔离；`0.70–0.95` → 打标投递；`< 0.70` → 正常 |
| BR-02 | 白名单命中直接放行，不受其他信号影响 |
| BR-03 | 认证失败/黑名单/信誉差/主题正则命中 → 直接判垃圾 |
| BR-04 | 垃圾邮件不进入业务分类、不参与自动回复 |
| BR-05 | 分类置信度低于 0.60 才调 LLM；LLM 结果必须是合法类别且置信度 ≥ 0.5 |
| BR-06 | 只有 `auto_reply_categories` 内的类别才可能自动回复 |
| BR-07 | 回复必须满足 11 项闸门（含 RFC 3834、冷却 24h、线程深度 ≤ 3、免打扰） |
| BR-08 | 草稿必须带有效引用；无依据 → 拒绝 |
| BR-09 | 出现价格承诺/折扣/赔偿/合同/保证 → 转人工 |
| BR-10 | 回复中出现身份证/银行卡/手机号 → 拒绝 |
| BR-11 | 来信含提示注入 → 不自动发送 |
| BR-12 | 只有发送成功才占用冷却名额；失败可重试 |

## 7. 状态机

见 `图示/05-状态图-邮件生命周期.md`。主状态：
`fetched → parsed → classified | quarantined → pending_review → replied`，另有 `failed`、`deleted`。

## 8. 非功能与部署约束

- 接口鉴权：生产必须配置 `MAILMIND_API_KEY`，且走 HTTPS；
- 凭据加密：生产必须替换 `MAILMIND_SECRET_KEY`，建账号后不可变；
- 数据库：开发 SQLite，生产 PostgreSQL；迁移由 Alembic 管理；
- 队列：默认同步执行（eager），生产可切 Celery + Redis；
- 对象存储：本地目录 / S3 兼容（MinIO）；
- 观测：结构化日志 + `trace_id` + `/health` + `/metrics/overview`。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| 三档动作 | pass（通过）/ tag（打标投递）/ quarantine（隔离） |
| 模糊区 | 模型分 0.20–0.80，交 LLM 复核 |
| 回复闸门 | 决定"这封能不能自动回复"的 11 项检查 |
| 护栏 | 对生成内容的安全校验（引用/PII/承诺/注入） |
| 冷却 | 同一发件人 24h 内只自动回复一次 |
| 草稿可用率 | 审核时无需修改即可发送的比例 |
| thread | 由 References/In-Reply-To 归并出的会话 |
